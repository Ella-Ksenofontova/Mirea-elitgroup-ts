Ответы на вопросы
=======

1. **Нет**, интерфейс `Student` не может запретить серверу присылать некорректные значения, потому что JavaScript, как правило, выполняется на клиенте. Решение - проверять приходящие с сервера данные.
2. Символ `|` означает, что объект может быть либо одного типа, либо другого, либо соответствовать обоим типам сразу. Очевидно, последнее условие может и не выполняться - это достигается при использовании символа `&`.
3. Тип mixed - (string | number)[]. Это говорит о том, что **любое** значение в массиве может быть как числом, так и строкой. Тип pair же говорит о том, что первое значение - строго число, а второе - строго строка. Получение имени и перевод в верхний регистр осуществляется так: `pair[1].toUpperCase()`. Однако метод `toUpperCase()` определён только для строк, а в mixed второе значение может быть и числом. Поэтому в этом случае нужны дополнительные проверки.
4. Тип `unknown` предотвращает ошибку, связанную с тем, что в функцию был передан параметр не того типа, который ожидался. Обработка пустого массива осуществляется с помощью `if (arr.length === 0)`. Однако если был передан примитив или объект, не содержащий свойства `length`, то может возникнуть ошибка.
5. Если мы функции `findById` передадим в качестве первого параметра `[{ name: "Анна" }]`, то IDE предупредит об ошибке, так как в объекте из массива нету поля id числового типа.
6. Функция `parseName` может возвращать два типа значений: `{ok: true, value: T}` (T - условное имя типа) и `{ok: false, error: string}`. Как видно, если ok принимает значение false, то в объекте отсутствует значение value (оно равно undefined). А для значения типа undefined не определён метод toUpperCase - у него вообще нет никаких свойств и методов. 
7. В успешном варианте возвращается `string`, потому что в самом начале тела функции мы отсекли вариант, при котором переданный параметр не является строкой.
8. " Анна " - {ok: true, value: {name: "Анна", group: "ЭГ-2", id: 1}}  
"  " - {ok: false, error: 'Имя не должно быть пустым'}  
42 - {ok: false, error: 'Имя должно быть строкой'}  
После ошибки создание студента не продолжается, так как при возникновении ошибки выполняется инструкция `return`. В JavaScript все инструкции после `return` игнорируются.
9. При значении ok, равном false (неуспешном значении), тип T (в данном случае это Result) не используется, что позволяет применить функцию `parseName` в данном случае.
10. Ответ на данный вопрос планируется представить на защите.
11. `npm run dev` преобразует код, написанный на TS, в JavaScript-код, а в JS строгая типизация отсутствует. Следовательно, проверка типов при запуске этой команды не осуществляется.
12. Инструкция `const` при инициализации объекта не позволяет переписать сам объект (`student = ...`), но его свойства менять можно.
13. При поиске отсутствующего элемента возвращается `undefined`, и такой случай должен быть представлен в сигнатуре.
14. Если тип значения `unknown`, то это значит, что мы не знаем его тип, а следовательно, и определённые для него свойства и методы. Поэтому при работе с таким значением нужно делать сужение типов.
15. При ok == true у объекта Result обязательно есть значение указанного типа, доступное по ключу value. При этом у объекта этого типа должно быть числовое поле id. В случае, если ok == false, в объекте Result нет значения с ключом value, однако есть строка с ключом error.
16. Одно из важных значений между `Pick<>` и просто созданием объекта с выбранными полями заключается в том, что `Pick<>` проверяет, есть ли эти поля в исходном типе, что позволяет поддерживать связь между исходным и производным объектом.
